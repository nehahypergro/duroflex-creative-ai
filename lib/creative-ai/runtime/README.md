# Creative AI local runtime

Run `PORT=1838 node server.js`, then open http://127.0.0.1:1838/creative-ai. Requires Node 20.9+, installed root dependencies, a server-side OPENAI_API_KEY and account access to gpt-6-luna and gpt-image-2. Configuration reads environment, root .env, then the existing nehacodex-v2/.env.local fallback. Credentials are never returned by the public API. This is a local demo; authentication and public deployment hardening are not implemented.

The UI accepts an official brand URL, optional brief/audience, public guidance or uploaded PDF, reference images, and multiple placements. It exposes the full 131-profile catalog and custom import. Generation availability is restricted to known single static raster dimensions and supported PNG/JPEG/WebP contracts; other profiles retain explicit gaps. Current demo limits: three placements, one active job, two concurrent units, 40 reasoning reservations, 45-minute dispatch deadline, and exactly two concepts. Each concept/placement permits one initial image and at most one consolidated correction image. Reservations survive restart; ambiguous paid requests are not silently repeated. New jobs also persist an estimated USD spend policy and reserve it atomically before every provider dispatch. The deadline does not forcibly cancel requests already in flight.

Live adapters collect bounded official pages, actual assets and a website screenshot; distinguish social/Meta access gaps; create an immutable dossier; then call brand guardian, strategist, creative director, and parallel copy/art planning. Reconciliation binds exact copy and source assets before gpt-image-2 renders the complete static, including text and identity. Export performs only whole-image resampling and encoding. Actual final bytes are checked with file measurements, Apple Vision OCR on macOS, and multimodal review. A score of at least 75 cannot override unknown/failed critical checks. The threshold is an initial, uncalibrated policy. Native publisher copy is delivered separately.

Atomic checkpoints, per-job process locks, creation request keys, image reservations, immutable artifact bindings, a hash-chained activity ledger, and a separate authoritative review ledger preserve provenance and the correction cap. This is not a distributed job service. Cross-process creation/global concurrency and every possible crash boundary have not been verified. A failed planning role is recorded and both parallel requests settle before releasing the job. Per-unit runtime failures preserve sibling outputs and make the job explicitly partial. Recovery does not authorize another creative cycle.

## Verification recovery and exact copy

Artwork inspection retries connection failures (network/timeout, HTTP 408/429/5xx) up to three attempts on identical package/image hashes. Each dispatch attempt is reserved in `review-recovery-*.json` before calling the provider; in-flight attempts remain spent after restart. Validated outcomes are reused without another call. Contract errors, authentication errors and budget exhaustion do not receive transport retries. Inspection errors that produce pending evidence do not spend an initial creative correction: the saved image is delivered as `verification-pending`. Genuine inspected creative defects still use the existing one-cycle flow.

A saved result whose consumed review is pending because of a connection failure exposes **Retry checks on this image**, backed by `POST /creative-ai/api/jobs/:id/retry-checks` with route/placement ID. This reserves one durable verification recovery, with at most three inspection attempts/six reasoning requests (including schema repairs). A 15-minute verification window permits checking an expired saved job; its original image reservations, reasoning-call limit and total estimated-spend ceiling remain unchanged. Images cannot be dispatched through this budget. Exhaustion or unverified evidence stays flagged; there is no readiness override. A recovered report may update delivery readiness through the ReviewLedger only when the same saved image/package passes the full policy. Original report hashes, report files, delivery files and correction count remain intact, with new report/delivery filenames and linked journal snapshots. Repeated recovery requests reuse the reserved/completed result and cannot open another recovery or image cycle.

Exact-copy inspection now requires a separate visual transcription for each locked/mandatory embedded field. A visibly separate CTA arrow/chevron is classified as a decorative icon and excluded from the transcription. Inline symbols, changed spelling, case, punctuation, missing words and extra words remain copy discrepancies. Ambiguous separation or uncertain glyphs remains unknown. The same rule applies to both routes. Matching visual transcriptions contradicting a failed exact-copy assertion require schema repair instead of silently forcing a pass. Independent OCR remains supporting evidence and matches full field boundaries; OCR confidence cannot establish visual legibility. Copy observations are saved separately for audit. This defines consistent rules, not calibrated evaluator reliability.

`tests/creative-ai/review-recovery.test.js` covers transport bounds/restart, same-image identity, no new images, immutable previous reports, terminal recovery/journal delivery, correction-cap preservation, expired-job scoring budgets, both routes' icon policy, genuine copy changes, uncertainty and OCR partial-word disagreement. All authored evaluator assertions in tests are isolated fixtures, not live creative-quality evidence.

## Strategist decision contract

New strategy inference now requires `strategyChecks` through the existing Marketing strategist: product focus, customer barrier/relevance, message role, proof limits, destination action/verification/fit and the weakest assumption with needed evidence. Validation runs before creative direction and remains in downstream package validation. Invalid claim wording is rejected rather than silently replaced with a canonical fact. The existing one schema-repair allowance and spending limits still apply; no new agent or image retry is added. Historical strategies remain unchanged/readable through the base version-1 contract.

Optional API campaign fields `productName`, `buyingSituation`, `buyingBarrier`, `desiredAction` and `landingPageUrl` enter the assignment. User-provided customer context is not measured research. A supplied landing URL is checked for public-network safety at intake; a URL alone is not destination verification. Missing page facts remain an explicit strategist research request. Product-name fallback uses the brand name; a redundant, already-overwritten `carry goods` assignment has been removed.

The brief now chooses `focusType` (`product`, `collection`, or `brand`). Product and collection briefs require an explicit `productPageUrl` on the selected brand's website. Naming a product through the API also requires a page. This is separate from optional `landingPageUrl`, which governs the campaign click destination. Brand-level free text is checked for named products before guardian/strategy; a named product moves the job to `needs-input`, with a product-page form in the UI. `POST /creative-ai/api/jobs/:id/product-page` supplies that reference and resumes the same job with its original intake, spending records, image reservations and deadline retained. Expired jobs cannot open a fresh generation window through this route.

Explicit page research runs before strategy and saves `research-sku.json`. It collects that page's title, text, structured SKU metadata and up to three product images from its own metadata/gallery; navigation and recommended-product images are not substitutes. Duplicate sizes of the same image are collapsed. A default SKU/size in page metadata is not a user-selected variant. Source snapshots are preserved by URL and attempt. Unrelated generic product photos and product facts are removed from this campaign context, while brand identity, tone and supplied guidance remain. Physical-product image auditing and product-name matching must pass; inaccessible pages, missing product photos or uncertain SKU matching request a correct page rather than falling back. Source passages attach through IDs, and clinical outcomes or numerical comparisons stay unverified; ordinary sourced physical specifications may be supported. SKU images take priority in visual context and every product hero must reference a verified selected-page image before image dispatch. The project displays the selected page and its verified image count.

Historical `research-brief-product.json` / `strategy-researched.json` checkpoints remain readable, and older completed jobs are not rewritten. Product research still uses the configured provider, existing reservation gates and bounded schema-repair policy.


## Static presets and carousel sequences

The brief separates creative treatment (benefits, launch, offer, lifestyle, education, comparison, testimony or event) from the output canvas. Studio presets provide explicit PNG dimensions for square/portrait/landscape social posts, vertical stories, pins, website and email heroes, product tiles, digital posters and infographics. These are selected job specifications; they do not replace the shared publisher catalog or claim publisher certification. Formats outside the image provider ratio envelope remain planning-only.

Square and portrait carousels support 2–6 slides, with at most 6 generated units per concept across a mixed selection. The UI shows the image count and disables oversized selections; the server enforces the same limit. Each carousel expands to uniquely pinned slide profiles. Existing two-concept, one-correction-per-unit, durable reservation, deadline and USD spend limits still apply to every slide.

After concept selection the creative director saves a shared story plan: an opening hook, distinct middle messages and a closing action, with supported fact IDs and one visual system. Copy and art planning receive that same plan and run in bounded placement batches. Repeated slide headlines are rejected. Generation processes both concepts for each slide before the next slide; a reviewed opening slide can be attached as a style reference to later slides of that same concept. Generated references never become SKU evidence or replace original logo/product sources. Corrected packages retain the slide narrative and selected SKU requirements.

Each slide receives the existing independent OCR, identity, claim and raster review. A separate review compares the actual ordered set for sequence, visual consistency and message continuity. A set is ready only when all slide and set checks pass. Missing slides or an interrupted set review stay explicit. Numbered ZIP exports include available slide bytes, review.json and a README that labels flagged or missing content. Reviews and bundles are bound to the slide manifest; status recovery creates a new filename rather than rewriting a historical report.

Art adapters supply a compact per-placement rule → source → evidence-status mapping and allowed art principle IDs. The model cannot treat editorial guidance as publisher evidence or use a placement-rule ID as an art principle. Repair diagnostics identify the affected annotation and the actual allowed source relation. Validation remains strict and schema repair remains bounded.

Validated art-stage recoveries with zero image requests can use `POST /creative-ai/api/jobs/:id/generate-recovered`. This starts one separate generation window on the existing project, revalidates the saved art and packages, and reuses the saved strategy, concepts, copy and layouts. It preserves the original deadline, call caps, spend policy and durable reservations; repeated requests never reset the recovery window or dispatch an already reserved image again. The attempt is recorded under `generationRecovery`, and exported images still pass through the normal review and single correction cycle. The project shows the action only before this attempt has been created.

## Cost optimisation — 11 October 2026

New reasoning requests use wire-only projections; authoritative saved records and semantic validators still receive complete inputs. Selected strategy decisions reach downstream stages without discarded alternatives. Artwork review receives the full art direction, exact copy, locked rules, source facts and identity bindings, plus the same target pixels, reduced viewing preview and original reference attachments. Duplicate prompt/planning history and serialized placement messages are omitted. Rule text, factual qualifiers and required copy are not truncated. The response schema is supplied once through the API response contract rather than echoed into the user message.

Brand guardian interpretation is stored under the selected brand's `knowledge-cache`. It includes only brand evidence, and is reused only after semantic validation. The key includes the complete brand input/source bytes, scope/revision, model, instructions, schema, cache version and pinned preference-memory revision. Changes invalidate reuse; invalid output is never stored. Each campaign attaches its own exact brief as campaign instructions after lookup. SKU research remains a separate fresh selected-page collection/audit on every new campaign; neither product knowledge nor past product approvals are reused by this cache. Original saved research-session accounting is unchanged, and cache reuse does not copy the creator's provider receipts into another job.

Reconciliation asks for bounded visual adjustments and per-field text layout. Code binds exact copy, unit identity, source logo/product references, rules, native fields and hashes. Unknown units, duplicate fields, missing text layouts or protected identity changes are rejected. The full existing art, provenance, copy-fit, guideline and SKU validators still run after assembly; one bounded schema repair remains. A compact rule-to-source mapping stays available during repair.

Scoped brand context and relevant preference/policy memory precede dynamic campaign input, with a brand/stage/model/schema cache key. Reconciliation's wire schema uses a stable structural unit-ID contract; code validates IDs against the selected units. This improves opportunities for exact-prefix prompt caching, but does not guarantee a provider cache hit. No unsupported retention override or model/quality downgrade is configured. See [OpenAI prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching) and [structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

Selected creative edits keep the existing immutable, one-unit refinement path. Planning inputs omit discarded strategy alternatives and duplicate placement messages; the parent campaign, other creatives, product evidence and prior reviews stay saved. New pixels still receive their own complete artwork checks. Receipt metadata now records stage, original/focused input character counts, stable-context size and output-contract mode alongside actual provider token usage. Character counts are diagnostics, not token or INR estimates.
