## Bugs fixed (both brands, each with a test that fails before)

1. **Products page too wide on a phone** (543 px on 375 px; phones zoom out): a cell's screen-reader label escaped the table's scroll box. `.product-table-wrap{position:relative}`. Test: `studio-phone-picker-20261119-browser.test.js`.
2. **Reloading the format picker failed** ("We couldn't complete this action" over "Loading…"): the replayed button had no `closest()`. Same test.
3. **Collection and Brand only** were offered for every format, then Check brief failed with "Choose a connected static recipe…" or called it a planning brief with no reason. Check brief and the inline create now say what to change ("… needs a product", "… is made for one product at a time"), and the brief can still be saved as a planning brief. Test: `brief-focus-unsupported-20261119.test.js`. (A first version made this an error and blocked Save brief; two existing browser tests caught it before commit.)
4. **No carousel ZIP or LinkedIn PDF for new carousels**: the lean flow never built the carousel package. Both are now built on request from the saved slides. Tests: `lean-carousel-export-20261119.test.js`, `studio-carousel-download-20261119-browser.test.js`.
5. **Back after a brand switch** left the address on the old brand while the page showed the new one (a reload or a copied link opened the other brand). Test: `studio-brand-back-20261119-browser.test.js`.
6. **Waiting jobs looked stuck**: a job waiting behind others (the Sleepyhead Brand Story waited 22 minutes) said "Creating · Planning · Creating your designs" with nothing moving. It now says "Waiting for a free slot. Other designs are being made first; this one continues by itself." Test: `studio-queued-wording-20261119-browser.test.js`.
7. **Web push failed in planning** (Hindi campaign, Airboost Duo Topper): "Mandatory rule cannot be omitted: feature-demonstration". That rule applies only "when a page's message is a physical product feature"; the planner said it did not apply and the job failed. New jobs pin `conditionalRuleVersion: 1`: a written "not-applicable" for this rule is recorded as applied with the planner's note, and the image check still judges it. Every other mandatory rule still fails on "not-applicable". Test: `conditional-rule-20261119.test.js`.
8. **A+ Basic failed in planning** (Duroflex Spine Contour Pillow): "Amazon text for image-3 needs a headline of 70 and a body of 300 characters or fewer", sent word for word to the one repair. It never said whether the text was missing, too long, or cleared by the A+ wording rules (for example a warranty not in the brief). Each error now names its cause and lists the removed wording, so the repair fixes the right thing. Pass/fail is unchanged. Test: `aplus-pages.test.js` (new case).
9. **Brand-only pictures could not be made** (Sleepyhead A+ Brand Story, brand only): all five pages were planned, then the picture step failed with "Image provider request failed (400): Invalid 'images': empty array". Every picture request went to the edits endpoint, which needs an input picture, and a brand-only page without the logo has none. No saved local job had ever been brand-only. Such requests now go to the generations endpoint, from the Studio and from the shared executor; requests with pictures are unchanged. Test: `brand-only-image-20261119.test.js`.

Fixed earlier today (pushed in `474bdb1`): corrections refused for "Teal sofa" protection, the stale "Artwork has not been created" page, and the missing INR rate file.

## Found, not fixed (decision or outside this code)

- **The local text reader is Apple Vision, macOS only.** On the hosted Studio (Linux) it is always unavailable, so these never run there: text size, spelling, the measured story safe zone and its one redraw, the label close-up for generation and checking, and AI-edit text areas. The checks return nothing, so nothing tells the user. Options: add a Linux reader (for example tesseract.js, calibrated against saved images and pinned for new jobs), install one in the server image, or at least show "not measured on this server".
- **Edit with AI on a button**: a pin's Medium area is a square; on a wide button it recoloured only the middle and reached the lines above and below. Text-shaped areas need the text reader above.
- **Custom size** in the Format list makes a planning brief only for social, website and email formats ("Image creation is not available for it yet"); the note is easy to miss. Print formats ignore a custom size.
- **Image-only formats** (email product block) accept a language and message type that have no visible effect.
- **Slow steps**: planning often passes 4 minutes (the backup model takes over, as designed); image checks take 4–6 minutes; only about two jobs plan at once, so a third waits as "Creating" with no progress shown.
- **Product data**: one Duroflex Posture Perfect Queen variant on the official website reads "(2.14 cm x 168 cm)".
- The product-page pack's spend check still describes 24 images ("PDP pair") from the two-option days, and reserves for 24.
- **Wide banner ends**: the 970×250 billboard is drawn at 3:1 and its two leftover ends are filled with one flat colour. The model was told to keep its ends plain but drew a room, so the banner shows two grey side bars with hard seams. The check flagged it (placement, realism, structure), but layout findings are never corrected, so the user gets a flagged billboard with no repair. This is not a one-off: 2 of the 3 billboards made so far have these strips (also Sleepyhead `creative-53dd9adb`, 9 Nov). The billboard adds 117 px of flat colour on each side. The saved "plain edge" measure (`exact-canvas` `edge.flat`) can't tell: it marked all 6 saved band banners busy, because a wall above a floor already counts as uneven. A fix would fill uneven ends with one masked image edit, the way edge fit works, at one extra image edit per affected banner. This needs a decision.
- **Opening a failed project directly** first shows the browser's saved copy, so it read "Creating · Planning" for about 20 s before "Needs attention". In those first ~30 s, while the project list refreshes, a click on "Review recovery options" can show nothing: the page redraws and the answer is dropped. A second click works. The page also keeps asking for the failed job every few seconds.
- The failure card says "Use Retry to try again", but its button is called "Review recovery options".
- **Product-page correction refused** with "Local repair requires product protection" (Sleepyhead Sofa Drip pack). Fixed in `474bdb1` earlier today; it reaches the hosted Studio with the redeploy.
- **Label placement**: on the Napster Mini A+ page the image model moved the orange label to the wrong face on 3 of 14 panels. The check caught all 3 (product / feature findings).
- **Label wording is never checked live**: the label close-up comes from the same text reader, so every A+ panel showing the label says `unable_to_verify` for `label-wording` and still counts as Ready.
