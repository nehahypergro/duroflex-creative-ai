# Edit with AI for new designs (8 Nov 2026)

## What it does
- New designs from the main lean flow have an **Edit** button on the design page. It opens the editor (the same dialog and "Edit with AI" chat as the earlier editor) in **image-only** mode: the saved artwork is the canvas. There are no text layers and no text reconstruction.
- The user can annotate with the earlier editor's tools: **Box** (drag a rectangle) and **Pin** (click a spot), up to 12 marks, numbered "Box 1", "Pin 2" and so on.
- Each **Send** makes one paid `gpt-image-2` (high) edit of the version in use.
  - With boxes, the boxes become one edit mask. After the edit, every pixel outside the boxes is copied back from the version being edited, so it stays exactly the same. This uses the lean correction tools (`correction.regionsMask`, `masked-image.pngMask/restore`). The 1-pixel outer border of the design is always kept, and boxes may cover at most about a third (35%) of the design.
  - Pins are named in the instruction ("Pin 2 at 40% from the left…"). They do not limit the change.
  - With no box, the whole image may change.
- The result is fitted to the exact format size (`exact-canvas.fit`) and saved as a new immutable version, a child in the existing `refinements` store. The original is never changed.
- A finished version is shown on the canvas but not selected. "Use this version" selects it, checking its exact hash. Edits always start from the version in use. The original can be restored the same way. Downloads, ZIPs, packs and feedback use the selected version.
- The text-only side panel from earlier today (`studio-ai-edit.js`) has been removed, so there is one editor.

## Safety and cost
- Each Send has its own request ID, so a retry or double-click never buys a second image. Only one edit can run at a time.
- Wrong brand, research from another brand, empty or too-long text, invalid or oversized marks, and stale selections are rejected before any call.
- The mask is saved with the child (`ai-edit-mask.png`), and its hash is bound in `creative-edit-anchor.json`. The brand-scoped provider refuses a mask that is changed or not bound.
- Receipts are counted by the cost ledger, which already scans `refinements/`. A running edit shows "Cost: shown when the edit finishes", never ₹0. A failed request with no receipt shows as unknown.
- Edited versions are marked **Not checked yet** and never show "Ready".

## Live check (whole-image edit, before annotations)
- Duroflex Cove WhatsApp card, "Change the wall colour to a soft light blue": only the wall changed. Output 1080×1080. One receipt: about ₹12.31 at ₹96.61/USD (RBI, 9 Oct 2026). A masked edit sends one extra mask image, so it costs about the same. A masked edit has not been run live yet.

## Code
- Server: `lib/creative-ai/runtime/lean-edits.js` (annotations, mask, restore) and `brand-isolation.js` (mask binding for `creative-edit-anchor`). Routes: `GET/POST /api/jobs/:id/ai-edits`, `GET …/ai-edits/:childId`, `POST …/ai-edits/selected`.
- Browser: `public/creative-ai/editor-image-only.js` and `.css`, `EditableCanvas.openImageOnly`, and `studio.js` (`leanEditable`, `openLeanEditor`).
- Tests: `lean-ai-edit.test.js`, `lean-ai-editor-annotate.test.js`, `lean-ai-edit-browser.test.js`. Screenshots are in `work/ai-editor-20261108/`.

## Limits
- There is no freehand drawing, because the earlier editor had only Box and Pin. There is also no moving of text layers.
- The AI can still change details inside a box that the user did not mention.
- An edit cut off by a restart is marked failed and is not re-sent.
- A pack built from an edited version has no copy text.
- An older, smaller design is edited at its own size and then enlarged to the format size.
- Page-to-page navigation for sets is not shown inside this editor. Close it and open the next page.

## Pins with comments replace boxes (9 Nov 2026)

The user asked: "i dont want box. just pins/comments that act as edits". This supersedes the Box and Pin tool description above for the editor screen.

**How it works now:**
- **Screen:** there are no Box or Pin tool buttons. Clicking the design drops a numbered pin and opens a small comment box beside it ("What should change here?", up to 300 characters).
  - Up to 12 pins, listed in the panel as "1 · comment", with an × to remove each one.
  - Clicking a pin or its row edits the comment.
  - Escape (or Enter) closes the comment box. A new pin with no comment is removed.
  - An optional "Anything else?" note sits below the pins.
  - Send is enabled once a pin has a comment or the note has text.
- **Server (`lean-edits.js`):** pins may carry `comment` (text, trimmed, ≤300).
  - `instruction` is now optional when a pin has a comment. At least one of the two is required.
  - The prompt lists `Pin N (x% from the left, y% from top): "comment"` under "PINNED COMMENTS".
  - Old box annotations are still accepted, so saved versions and their history stay valid. The screen just no longer offers boxes.
- **Pins image (`edit-pins.js`):**
  - A deterministic copy of the version being edited, with numbered markers drawn on it.
  - Saved in the child as `ai-edit-pins.png` and bound by hash in `creative-edit-anchor.json` (`pinsName`, `pinsSha256`).
  - Sent as Image 2 (`creative-edit-pins`), with the instruction never to draw pins in the output.
  - `brand-isolation.js` accepts it only next to the bound edit anchor, and only when its bytes match the binding and a rebuild from the anchor and the saved marks.

**Honest limit:** pins don't mask the image. The whole picture is regenerated with the pins as guidance, so things away from the pins can shift slightly. Every edit is still a new version marked "Not checked yet", and the original is never changed.

**Cost:** about ₹13 per Send (estimate). The pins image adds one small input image.

**Tests:** `lean-ai-edit-pins.test.js` (new, 4 tests, both brands), plus the updated `lean-ai-editor-annotate.test.js` and `lean-ai-edit-browser.test.js`. The browser test covers no Box tool, click-to-pin, comment-only Send, Escape behaviour, and 1366 and 390 widths.

## Pin areas protect the rest of the design (9 Nov 2026)

**Why:** the live pin test (job `creative-a18acace…`, ₹13.12) changed the books and the pot correctly, but the whole picture also zoomed in slightly. The user then chose "Yes, protect it".

**How it works now:**
- **Areas:** each pin has an area that can change, Small, Medium or Large: a square of 16%, 26% or 42% of the design's shorter side, kept inside the design.
  - New pins start at Medium.
  - The area shows on the design as a dashed square and can be changed in the pin's comment box.
- **Mask:** the squares become the edit mask, the same restore path boxes used:
  - fit to the anchor's grid;
  - copy back every pixel outside the squares;
  - refuse the result if any outside pixel changed;
  - then fit to the exact format size.
- **Size limit:** the squares together may cover at most about a third of the design. The editor disables Send above that, and the server refuses it before any paid call.
- **Where the sizes live:** `edit-pins.js` holds `AREAS` and `areaOf`. The editor repeats the same numbers, and the browser test checks that the drawn square matches the server size.
- **The note:** with pins, the note applies inside the pinned areas. With no pins, the note can change the whole picture. This is the way to ask for whole-picture changes such as lighting.
- **Older pins:** pins saved without an area (earlier on 9 Nov) keep the unmasked, guided behaviour.
- **Limit:** a change bigger than a Large square, such as a whole wall, needs the note without pins.
- **Tests:** `lean-ai-edit-pins.test.js` (7 tests: both brands, exact mask, 0 changed pixels outside the areas, oversized and unknown areas refused, older pins unmasked) and `lean-ai-edit-browser.test.js` (default Medium, drawn square size, Small switch, size limit and warning clearing, phone layout).

### Line-up before restore (9 Nov 2026 engine fix)

**Symptom:** in the first live pin-area edit (₹13.14), the protection held: 0 pixels changed outside the areas. But gpt-image-2 returned the whole scene about 4.5% zoomed and slightly shifted, so the restored original met a misaligned redraw. The seams were visible: a doubled Kannada text line and a broken mattress edge.

**Fix (`edit-align.js`):** before the restore, the model's output is matched to the version being edited.
- The match uses an even zoom and a shift only, searched on the protected pixels. There is no stretching or rotation.
- The output is then resampled onto the original's pixel grid.
- The line-up is applied only when it clearly improves the match (at least 15% better). Otherwise the output is used unchanged.
- The result is recorded as `aiEdit.alignment` (`scale`, `dx`, `dy`, `before`, `after`, `applied`). The aligned image is saved as `ai-edit-aligned.png`.
- This applies to every masked edit, both pin areas and older boxes.

**Results:**
- Replaying the live files: the mismatch fell from 31.0 to 7.7 and the seams disappeared (`work/ai-editor-20261108/align-replay-closeup.png`).
- Regression test (`lean-ai-edit-pins.test.js`, "lined up"): the seam measured 37.7 before the fix and 2.5 after, for both brands.

**Automatic correction (also done 9 Nov 2026):** new lean jobs pin `correctionAlignVersion: 1` (`lean-policy.configure`, copied by `provider-config.snapshot`).
- In `lean-workflow.js correct()`, the corrected image is fitted to size, then lined up with the original (`edit-align.js`) before the protected pixels are restored.
- The result is recorded as `state.candidateAlignment`.
- Jobs pinned earlier keep their saved restore contract.
- Regression test (`lean-main-flow.test.js`, "lined up with the original"): the seam measured 44.3 before the fix and passes after, for both brands. The check that nothing outside the region changed still holds.
