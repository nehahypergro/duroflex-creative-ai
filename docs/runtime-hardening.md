# Reference storage, corrections, review and recovery

New campaign and research jobs use storageVersion 1. Their JSON artifacts store raster references containing the decoded image SHA-256, brand namespace, byte length and original encoding prefix. Immutable blobs live at output/creative-ai/reference-images/<brandId>/<sha256>.bin. Identical bytes share a blob across that brand's jobs, research sessions and child versions. Different brands retain separate storage. Reads verify ownership, length and SHA-256 before reconstructing the original strings; existing logical package and source hashes remain unchanged. Physical artifact hashes bind the JSON as actually stored.

Historical jobs keep their existing storage and evidence. No migration or deletion runs automatically. Supplied source archives and derived, self-contained PDF/HTML/ZIP exports may still embed images for portability. Back up the entire output directory, including reference-images; job directories alone no longer contain every referenced byte.

Copy and art corrections return a bounded changes object for one selected concept and placement. Every permitted field is present; null preserves its saved value. Identity fields cannot be patched. Code reconstructs the full output and applies the existing schema, source, placement and exact-copy validators. Other units are preserved locally. The existing single correction-cycle limit remains in force.

Visual review requests use fixed required keys for every critical and quality criterion, exact-copy field, applicable readability field and the four SKU observations. The runtime decodes these into the existing evidence arrays. Missing, foreign or mismatched entries fail validation. Complete evidence does not imply approval: unknown/uncertain observations remain unverified, and existing evidence-method, confidence, source-authority and product checks still apply. No extra reviewer or extra image request is introduced.

Reasoning requests derive a stable identity from the model, instructions, contract, input, attached image hashes and output/recovery settings, with a distinct key for each of the two bounded attempts. Successful raw provider responses are saved before their billing receipt and before downstream validation. Restarting replays the saved response, revalidates it and idempotently records its receipt. Image replay also verifies the compiled prompt, model, size, format and actual attachment hashes against the original request. A completed stage must match its saved physical artifact hash; missing or changed artifacts fail instead of silently recomputing.

A reserved request with no durable response has an ambiguous outcome and blocks redispatch. This includes a network timeout or a crash before the response could be saved. Reservation allowances remain separate from actual provider usage; the system does not invent receipts, reset budgets or promise provider-level exactly-once execution. Recovery remains single-process local persistence, subject to existing budgets and deadlines for new dispatches. Operator investigation is required for ambiguous requests.

The regression suite uses temporary stores, synthetic rasters and mocked providers. It checks deduplication, brand boundaries, corruption/missing blobs, legacy compatibility, bounded patches, complete evidence, receipt conflicts, response replay, ambiguous failures and stage hash validation without paid image generation.
